Report the factory state of this project. Read only - change nothing.

1. If `.factory/active` is missing, say "factory is not initialised in this
   project" and stop.

2. Counts, from `tasks/backlog`, `tasks/in-progress`, `tasks/done`,
   `tasks/blocked`:

   ```
   backlog=N  in-progress=N  done=N  blocked=N
   ```

3. **Ready now** and **4. waiting on dependencies**, both from one command:

   ```bash
   factory-ready
   ```

   `READY <id> <module> <title>` is dispatchable now; `WAIT <id> needs <ids>` is
   waiting on those; `HOLD` is needs-human; `STALL` is a task the gate has
   already shown is not moving. Print them as two lists, and do not recompute
   the dependency arithmetic yourself.

5. **In progress**: `id - title - owner - stage - how long in that stage`
   (from `owner`, `stage`, `stage_since`), plus whether `.factory/verified/<id>`
   already exists. Call out any task missing `owner` or `stage`: the Stop hook
   blocks on those.

6. **Dispatched agents**: two records, and they are worth comparing. The task
   files say who holds what (`owner`, `stage`, `stage_since`); the event log
   `.factory/events.jsonl` says which dispatches are still open - an
   `agent_start` with no `agent_stop`, minus anything a `sweep` line has
   written off. `running=` in `.factory/statusline.txt` is that count.
   List who holds what and for how long, and mark any agent silent for more
   than 7 minutes. Where the two records disagree, say so plainly rather than
   picking one: a task that claims an owner while no agent is open is a task
   whose agent died with its session, and it needs re-dispatching.

7. **Blocked**: `id - title - reason` (read the `## Blocked reason` section or the
   last review findings from each file), plus `retries` from the frontmatter.

8. **Stalled**: every file in `.factory/no-progress/`. Each one is a task whose
   last two gate runs failed on the identical error, so its retry budget is
   beside the point - it needs a different approach or a human. Print
   `id - signature - attempts` and mark these ahead of ordinary blocked tasks:
   an ordinary block is waiting for something, a stall is waiting for a decision.

9. **Test census** from `.factory/baseline.json`: `test_files` and `skipped` as of
   the last green gate, and when. A skipped count that is climbing is worth
   saying out loud even when nothing is red.

10. **Needs-human queue**: every task with `needs_human: true`, wherever it sits,
   with one line on what is needed from me.

11. **Last 5 decisions** from `decisions.md`.

12. **Gate config** from `.factory/config.json`: `gate_mode`, `workers`,
    `retry_limit`, `gate_isolation`, how many `risk_paths` patterns, and the
    four commands. Also `factory_version` - the harness version this project was
    initialised with. If it is behind `factory-version`, say
    so in one line: the project's `gates/verify.sh` was generated by the older
    one and does not carry whatever the newer gate template added.

13. **Changes** from `factory-change list` (read-only):
    one line per change - status, id-slug, done/total, type - with the path of
    its `summary.md`. `unsynced` means every task is done but no sync has closed
    it, so it has no `refs/factory/` ref yet and its summary is stale: the fix is
    `factory-change sync`, which this command does not
    run. Tasks in done that no commit carries show as `uncommitted` in their
    change's summary; name them.

13b. **Change acceptance**: a change listed as `unverified` has every task done
    and its own acceptance command still to prove. Name it, quote the command
    from its `goal.md`, and say what the last verdict was
    (`factory-accept <id> --show`). This outranks the
    task counts: the board says finished, the change does not.

14. **Lessons**: for each file in `.factory/lessons/`, the module and how many
    lessons it holds out of 15. A full file is worth mentioning: the next
    approved lesson for it has to retire an old one.

15. **Task files that would not dispatch cleanly**, from
    `factory-lint --all`: every line that is not
    `LINT OK` is a defect in a task file that will cost an agent's turn when it
    is dispatched. Print them verbatim; they are all fixable in seconds.

16. **Open questions** from `factory-ask list open`:
    each one with its task and what it is waiting for. These outrank everything
    else in the report - the run cannot finish them without me.

Finish with a single recommended next action, and remind me that
`.factory/dashboard.html` shows all of this live while a run is going
(`/factory:dash` opens it).
